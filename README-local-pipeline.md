# 本地照片到 Gaussian Splat 流水线

当前页面已接入本地流水线代码：浏览器选中的原始照片会上传到 `server/reconstruction_server.py`，服务按顺序执行 `pycolmap` 的 SIFT 特征提取、影像匹配、增量式 SfM / Bundle Adjustment，然后把 COLMAP 数据交给官方 Brush CLI 训练并导出 PLY。任务完成后，三维视口使用 Spark 渲染真实高斯（位置、球谐颜色、透明度、各向异性缩放和旋转），Point 模式单独显示带颜色的高斯中心点。COLMAP 拍摄视角可从下拉菜单切换；当前只提供真实 PLY 下载，没有 `.splat` 导出转换。

首次安装（Node.js 22、pnpm 10、Python 3.12；当前服务使用 Python 3.13 已移除的 cgi 模块）：

```bash
pnpm install --frozen-lockfile
python3.12 -m venv .venv
.venv/bin/python -m pip install -r server/requirements.txt
```

从 [Brush v0.3.0 官方发布页](https://github.com/ArthurBrussee/brush/releases/tag/v0.3.0) 下载适合系统的程序，解压到 `tools/brush/`，或设置 `BRUSH_BIN` 为可执行文件的绝对路径。程序本体不提交到 Git。

启动服务：

```bash
./.venv/bin/python server/reconstruction_server.py
```

另开终端启动页面：

```bash
pnpm dev
```

浏览器打开 `http://127.0.0.1:3000/`。请在参数抽屉中导入至少两张有重叠的本地照片；预设样本只包含演示元数据，不能提交给 COLMAP。

## 公网预览发布

`.github/workflows/pages.yml` 在推送到 `main` 或手动运行时检查、构建并上传 `web-preview` artifact。当前账号不支持私有仓库的 GitHub Pages，因此源码保留在私有 `3DGSMAP`，公网网页构建单独发布到公开 `3DGSMAP-preview` 仓库的 `main` 分支，由 Pages 部署。后续更新需从构建 artifact 同步文件到该预览仓库；源码仓库的 Actions 不会自动跨仓库推送。

构建基路径为 `/3DGSMAP-preview/`。公网预览只发布 `dist/`，不包含照片或任务数据，也不会部署 Python、COLMAP、Brush 服务。没有配置重建 API 时，页面显示预览提示并禁止提交重建任务。本地页面继续使用 `127.0.0.1:8787`。如需公网训练，需单独部署并保护后端，然后设置构建变量 `VITE_RECONSTRUCTION_API_URL`；当前 localhost 服务不是生产级公网 API。

`runtime/`、`.venv/`、`tools/`、`node_modules/` 均已排除出版本控制。运行中的任务只保存在内存和本地目录，请不要为部署前端而重启后端。

## 本地性能优化（API v2）

参数页新增独立计算档位，不再固定提交 30,000 步；共享配置在 `config/reconstruction_profiles.json`：

| 档位 | SIFT 最长边 / 特征上限 | 训练步数 / 最长边 | 点数上限 / SH 阶数 | PLY 导出间隔 |
| --- | --- | --- | --- | --- |
| 快速预览（默认） | 1600px / 4096 | 3000 / 960px | 50万 / 1 | 1000步 |
| 均衡 | 2000px / 6144 | 8000 / 1280px | 100万 / 2 | 2000步 |
| 完整质量 | 3200px / 8192 | 30000 / 1920px | 400万 / 3 | 5000步 |

快速、均衡档 SIFT 从原始尺度开始（first_octave=0），完整质量保留 -1。所有档位保留全部输入照片，但降低分辨率和特征上限可能影响匹配成功率、细节与最终质量。用户自定义点数上限覆盖档位值。无序照片默认全量匹配；有序航拍/视频帧可选择相邻匹配（按文件名顺序），避免全量成对匹配的开销。请勿把无序照片误选为相邻匹配。

- 单线程任务队列和跨服务文件锁确保新版服务同一时刻只有一个计算任务，减少共享内存/GPU 争抢。旧版正在运行的进程没有文件锁，不能与新版并发启动生产计算。
- COLMAP 子进程限制为最多 4 个 CPU 线程，原始日志持续写入各任务的 `colmap.log`；Brush 使用伪终端读取 indicatif 输出，持续写入 `brush.log`。服务不会把轮询请求日志刷满终端管道。
- 照片 multipart 上传流式写盘，避免将整组照片复制到 Python 内存；重复文件名会被拒绝。
- `runtime/sfm-cache/` 按照片文件名、内容、COLMAP 版本与解算参数缓存数据库和稀疏模型。相同输入修改训练步数/点数时跳过解算；更换影响 SfM 的档位或匹配模式会重新解算。失败解算的数据库保留，再次提交可复用已提取特征。
- `status.json` 持久化任务状态。重启后未完成任务标为中断，需要重新提交；不宣称恢复 Brush 优化器状态。中间 PLY 保存到任务 `output/` 目录，最终步数 PLY 存在才标记完成。
- 前端每 2 秒串行轮询，显示 SIFT 完成张数、真实训练步数和观测到的速度，训练 ETA 是样本估算、不含导出。原有加权总进度并非真实时间完成比例。

启用方式：待旧任务结束后关闭旧 API，再执行 `./.venv/bin/python server/reconstruction_server.py`。不要仅为加载代码而终止仍需要的训练。新页面检测到旧 API 会阻止提交新档位，以免旧服务忽略参数后继续按 30,000 步运行；已有任务仍可查询。

验证命令：

```bash
./.venv/bin/python -m unittest discover -s server/tests -v
pnpm lint
pnpm build
# 独立临时端口与目录，真实数据短流程；会运行两次 10 步的小规模训练：
./.venv/bin/python server/tests/smoke_api.py /absolute/path/to/jpg-images
```

2026-10-01 本机测试：用户的 13 张照片在快速档 COLMAP 用时 8.3 秒，13/13 相机注册、1262 个稀疏点、平均重投影误差约 1.106px；旧任务曾生成 6702 个稀疏点。隔离的 320px、2 帧、10 步 Brush 测试用时 5.7 秒，读取到第 5/10 步并生成最终 PLY。另一次 HTTP 集成测试使用全部 13 张照片、320px、10 步，验证连续提交两任务排队执行、缓存命中和 PLY 下载。这些短测试证明调用可用，不代表完整训练质量或固定加速倍数。

## 真实成果查看与快速档增密修复

- `GS` 渲染完整高斯，`Point` 为诊断视图（最多采样 20 万中心点）；真实任务禁用尚未生成的 Mesh/AT 示例图层，不以演示地形兜底。
- `GET /api/jobs/<id>/view` 从该任务 COLMAP 模型读取相机内外参，前端将 COLMAP 的 +Z/+Y-down 相机转换为 Three.js 的 -Z/+Y-up 相机。无相机数据时使用包围范围取景。
- 成果地址 `http://127.0.0.1:3000/?job=<id>` 可直接恢复已完成任务；新完成任务会更新地址，并尽可能在浏览器保存名称/参数。此地址只指向本地 API，不上传照片到公网。
- 快速档原先沿用每 200 步增密、1500 步停止，少量稀疏点时只有约 7 次增密机会；改为每 50 步增密、2250 步停止。均衡档每 100 步增密、5200 步停止，完整质量保持每 200 步/15000 步。最终点数依然取决于梯度阈值与照片覆盖，点数上限不是保证值。增密会增加计算量。
- 快速预览与照片级重建质量不同；重复纹理、反光和不足的视角覆盖仍可能产生模糊/漂浮。界面显示实测高斯数量与训练档位，不用“超高精度”代替质量评估。

2026-10-01 视觉回归：同一组 8 张会议室照片、3000 步、960px，原设置导出 1,173 个高斯；调整增密后导出 22,065 个高斯，复用 SfM 缓存后总用时约 5 分 35 秒。Chrome 实测 GS 与 Point 渲染、8 个真实相机视角、复位、最终 PLY 下载、任务切换后空状态；构建、类型检查及 8 项 Python 测试通过。新成果能呈现照片中的会议室结构，但仍有模糊和拉丝，不代表照片级重建质量。

## 本地项目自动保存

新建项目、任务参数、照片元数据和导入的原始 `File` 自动保存到当前站点的 IndexedDB（`3dgsmap-local-workspace`）。保存状态在后台维护；保存失败显示浮动提示并可重试，尚未完成保存时离开页面会触发浏览器提示。恢复时重建照片预览 URL，原文件仍可提交给 COLMAP，无需重新选择。

元数据与新增照片使用同一事务提交；参数修改不会重复写入未变更的照片，未改变的记录不会覆盖另一标签页创建的项目。此存储属于当前浏览器及站点来源（建议始终使用 `http://127.0.0.1:3000`）；更换浏览器、使用隐私窗口或清除站点数据不会保留这份浏览器数据库。训练服务已有的照片、缓存和 PLY 仍独立保存在 `runtime/`。

验证：独立 Chrome 数据目录中创建项目、导入两张照片、修改档位，关闭浏览器后重新打开，项目、参数及可显示的缩略图均恢复，恢复文件的 SHA-256 与原件一致。另验证双标签页新增项目互不覆盖，以及注入存储失败后显示错误、重试成功。类型检查与生产构建通过。

## 开发者接入页面

“开发者 SDK”页面现在按当前项目和任务展示实际 HTTP 接口，不提供虚构的 SDK 安装包或模拟执行日志。支持 `/api/health`、`/api/jobs/{job_id}`、`/api/jobs/{job_id}/view`、最终 PLY 下载及 `/api/reconstruct` 提交示例。Python、浏览器 JavaScript 和 cURL 示例使用当前任务 ID、照片名称及支持的计算参数；性能档位直接读取共享配置。

页面每 5 秒读取服务与当前任务状态；测试按钮仅发送 GET 请求，显示原始 HTTP 状态和响应。POST 示例需要开发者手动执行，会创建新任务。未提交任务、服务离线和未完成成果均有明确提示。页面同时列出尚未实现的 GCP 平差、DOM/DSM、网格、SPLAT 转换及云端能力。此页面变更不需要重启训练 API。

## 项目重建数据报告

报告按当前任务的 `pipelineJobId` 读取真实状态和 `/view` 相机内参，每 5 秒刷新。统计字段直接来自 COLMAP / Brush 任务记录；重投影误差显示三位小数，稀疏点显示精确数量，相机焦距和主点坐标使用像素单位。任务总历时取开始与结束（运行中取读取时刻）的时间差，包含等待和系统休眠；Brush 独立耗时仅在原始日志提供 `Training took` 时显示。

未采集的 GSD、重叠度、覆盖面积、检校先验、畸变、GCP / 检查点 RMSE、阶段耗时均明确标注不可用，不生成 Grade A+ 或测绘规范达标结论。无真实任务或连接失败时不回退到预设报告。支持导出当前快照 JSON，或打开完整报告的打印视图，由浏览器另存 PDF。
