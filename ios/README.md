# 3DGSMAP Capture · iPhone 原生采集

本版新增视频「系统 HDR」，与原来的「自动压曝光」及「关闭」组成互斥单选。开启 HDR 会停用应用曝光算法并复位补偿；切换原方案则显式关闭 HDR。旧设置自动迁移，拍摄中禁止切换；照片只提供关闭和自动压曝光。[能力边界](../docs/HIGHLIGHT_PROTECTION.md)。

当前源码版本 **0.2.11（build 13）**，最低 iOS 17。SwiftUI + AVFoundation + Core Motion，无第三方 iOS 依赖。

上一版增加照片/视频通用「自动防强光」开关：在拍摄界面右上角配置中开启，首次默认关闭并记住选择。使用预览大小的实时画面，每半秒抽样分析亮度分布，通过连续自动曝光和曝光补偿保护大面积亮部；在 0 至 −1.5 EV（受硬件支持范围限制）之间缓慢调节，关闭后恢复 0 EV。录制、保存或间隔拍摄中不能切换，开启后录制期间仍会自动适应光线。不改变保存分辨率，不修改已有素材。暗部可能变暗，无法消除光学眩光或恢复超出传感器动态范围的细节。

视频拍摄设置还提供「视频防抖」，首次使用默认关闭。需要更平滑的录像时开启，实际使用 AVFoundation 标准防抖；不支持的相机/分辨率不能开启，录制期间禁止切换。选择会保存在手机，下一次拍摄沿用。防抖可能裁切和轻微变形画面，重建采集优先保持关闭；开关只影响之后拍摄的视频。

已拍视频支持「保存到相册」与「导出到文件」，批量或单段保存均复制原片、保留 App 内原件。默认本机导出目录支持电脑文件共享，可用数据线取到训练电脑。操作说明见 [视频本地保存](../docs/VIDEO_LOCAL_EXPORT.md)。

本版改进大视频上传准备与界面响应：独立文件工作 actor、4 MiB 有界缓冲、校验缓存、独立进度区域和续传恢复。批次页面使用惰性布局，进度更新不再刷新整个素材列表。编译/回归由 `Validate iOS capture` workflow 执行；原有 0.2.6 真机分辨率报告不能作为本版上传或闪退修复验收。更新说明和待验收项目见 [CAPTURE_UPLOAD_UPDATE.md](../docs/CAPTURE_UPLOAD_UPDATE.md)。

## Mac 编译与安装

1. 克隆仓库，或下载并解压 `release/GSMapCapture-iOS-source.zip`，保留完整 `ios` 文件夹。
2. 用 Xcode 打开 `ios/GSMapCapture.xcodeproj`。无需 CocoaPods 或 Swift Package。
3. 在 target **GSMapCapture → Signing & Capabilities** 中选择自己的 Team，并使用自己可签名的 Bundle Identifier。工程中保留了当前安装使用的标识；首次在其他账号运行时需调整。
4. 连接并解锁 iPhone，信任 Mac，按系统提示启用开发者模式，再选择手机作为运行设备。
5. 点击 Run，首次拍摄允许相机访问。视频不录音，不申请麦克风权限。

模拟器编译：

```sh
xcodebuild -project ios/GSMapCapture.xcodeproj -scheme GSMapCapture -sdk iphonesimulator -configuration Debug CODE_SIGNING_ALLOWED=NO build
```

模拟器没有真实后置摄像头，只用于界面验证。相机不可用时，分辨率切换和拍摄按钮不可用。

使用免费 Personal Team 安装的开发版本需要定期重新签名。已有手机数据时，保持原 Team 和 Bundle Identifier，通过覆盖安装更新；不要先卸载 App。

## 采集操作

1. 我的项目 → 新项目 → 照片采集 / 视频采集。
2. 视频需横置手机。按提示站在房间边缘、背靠墙面，依次完成水平、仰视、俯视、物体细节四阶段。允许跳过阶段，成功保存后才进入下一步。
3. 点击右上角配置按钮，选择 **4K（3840×2160）/ 1080p（1920×1080）**。相机实际切换采集配置，成功选择后自动记住；视频固定 30 fps。
   视频模式下可开启「视频防抖」，相机支持且实际启用时显示「已生效」。模拟器没有真实相机，开关禁用。
4. 照片使用足够尺寸的原生相机像素，按 16:9 居中裁切并缩小至所选尺寸；竖拍宽高互换。不会将低分辨率来源放大为 4K，像素不足时显示错误。
5. 录制、保存或间隔拍摄中不能切换分辨率。配置失败显示错误并恢复之前设置。
6. 照片支持手动拍摄、2 秒间隔拍摄和上一张照片半透明参考。视频参考线可在设置中手动调节，参考线与引导图不会写入素材。
7. 素材和项目索引保存在 App 内，可离线采集。打开采集批次 →「保存视频到手机」，选择「保存到相册」或「导出到文件」复制已有视频；单段可在视频预览底部保存。原件和记录保留，保存前系统相册中没有这些文件是正常的。
8. 项目内采集记录左滑 → 删除 → 二次确认。删除本机记录及所属素材，不删除电脑上已经提交的训练任务。

## 上传与电脑联调

客户端实现了局域网地址/密钥设置、分块上传、任务状态与 WebKit 成果查看。手机接入网关（如 `mobile_gateway.py`、`capture_ingest.py`）当前不在此仓库；不能将已有的 `server/reconstruction_server.py` 直接视为兼容的手机网关。

如已有兼容网关，手机与电脑连接同一 Wi-Fi，在 App 填入实际电脑局域网地址和连接密钥，检查连接后上传。密钥存放在系统钥匙串；上传期间保持 App 在前台。

档位保持 `preview` / `balanced` / `quality` 标识，显示 15,000 / 30,000 / 45,000 步；实际执行步数由电脑配置决定。本机 3DGSMAP 已按此映射部署。电脑的手机接入区域兼容现有上传协议，不要求 APP 增加通知接口。首次校验仍需读取原件，但显示已处理容量；已完整校验且未改变的文件可复用缓存。退出页面或进入后台会暂停，重试以电脑确认的分块为准。

本次没有完成手机上传、断线续传、训练和三维成果端到端联调。电脑端现有独立流水线见仓库根目录 `README-local-pipeline.md`。

## 已执行验证

2026-10-13，0.2.10 在 iPhone 13 真机完成自动防强光验证：1080p 和 4K 开启后收到真实分析帧，实际曝光分别约 −0.4 / −0.6 EV；关闭后停止分析并恢复 0 EV。两个横屏方向共 12 个照片/视频尺寸全部匹配，视频 30 fps；录制中拒绝切换，结束恢复原设置。测量报告见 `docs/validation/highlight-protection-v0.2.10.json`。这些数值来自测试当时的画面，不是所有场景的固定补偿。

2026-10-12 在 iPhone 13 / iOS 26.2 上完成签名、安装、启动与真实分辨率切换：1080p → 4K → 1080p，每档位在两个横屏方向分别生成照片和约 2 秒视频，共 12 个文件。直接读取 JPEG 尺寸和 MOV 视频轨道后全部通过，6 个视频均为 30 fps，录制中切换均被拒绝。测试素材由独立测试入口生成并清理，不加入用户项目。

照片编码回归和模拟器设置/四步引导回归通过。完整报告位于仓库的 `docs/validation/iphone13-resolution-v0.2.6.json`；测试方法见 [Tests/README.md](Tests/README.md)。源码压缩包包含 `ios` 与本地导出操作说明，完整测量报告请在仓库查看。

## 源码结构

- `CameraService.swift`：相机配置、真实分辨率切换、拍照/录像、方向与运动提示。
- `PhotoResolutionEncoder.swift`：照片方向规范化、16:9 裁切、尺寸与元数据处理。
- `CaptureModels.swift` / `CaptureStore.swift`：采集状态、项目索引、素材归属和删除事务。
- `CaptureViews.swift`：项目、四阶段引导、相机界面和配置面板。
- `MobileConnection.swift` / `TransferViews.swift`：电脑连接、上传及成果客户端。
- `VideoLocalExport.swift`：添加视频到相册、系统文件副本导出和本地保存状态。
- `Tests/`：状态、删除、照片编码及 UI 回归源码。

`generate_xcode_project.py` 可生成基础工程；已有签名配置时不要直接覆盖现有工程。仅 Debug 版本在显式传入 `--verify-capture-resolutions` 启动参数时运行真机分辨率测试，正常启动不运行测试。

2026-10-13，0.2.11 在 iPhone 13 上完成 HDR → 自动压曝光 → 关闭 → HDR 的 1080p／4K 真机验证：相机 HDR 标志和曝光分析互斥，8 段实际视频分辨率正确、均为 30 fps，录制中切换被拒绝，结束恢复原设置。既有 51 个素材（含 17 段视频）的名称、大小、修改时间及项目索引完全保留。[测量报告](../docs/validation/highlight-modes-v0.2.11.json)。
